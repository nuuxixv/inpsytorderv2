# 사양 시트 — A11 행사 생성 페이지 (`/admin/events/new`)

> 이 시트는 **신규 행사 생성 흐름**의 정보·기능·데이터 구조의 단일 진실 소스다.
> 시안과 실서비스 구현은 이 시트의 모든 항목을 1:1로 반영해야 한다.
> 임의 단순화·통합·생략은 건우님의 명시적 승인 후 이 시트를 먼저 갱신한 다음에만 허용된다.
> 신설: 2026-07-20 (건우님 "행사 추가가 너무 복잡하다" → 모달 폐기·단일 페이지 전환 확정).

## 설계 목표 (건우님 확정 문구)

> **"이걸 페이지네이션한다고 해서 좋은 게 아니야. 그저 번거롭지 않게, 막힘 없이 생성하도록 하는 게 목표야."**

**스텝 분할(위저드)은 명시적으로 기각됐다.** 스텝은 클릭과 화면 왕복을 늘릴 뿐 마찰을 줄이지 않는다. 마찰의 실제 원인 3가지를 정면으로 없앤다:

| 기존 병목 | 해법 |
|---|---|
| 13개 필드가 한눈에 다 보여 "전부 채워야 하나" 압박 | **필수 3 / 선택 7 시각 분리**, 선택은 접어둠 |
| 좁은 모달(`maxWidth="sm"`) 세로 스크롤 | **전체 페이지 2열 레이아웃** |
| 저장 눌러야 알게 되는 검증 실패 | **입력 즉시 인라인 검증**(slug 형식·중복 포함) |

**최단 경로 = 드롭다운 3번 → 자동 완성 → 기간 2클릭 → "행사 만들기".**

## 범위 결정 (건우님 확정 2026-07-20)

| 항목 | 결정 |
|---|---|
| 화면 형태 | **단일 페이지·스텝 없음.** 모달 → 전체 페이지 전환(위저드/스테퍼 미채택) |
| ① 행사명 선택 | **현행 조립 방식 유지** — 연도+행사구분+주최학회 → 행사명·주문 URL 자동 조립, 수동 수정 가능. (과거 행사 복제 **미채택**) |
| 행사 기간 | **필수로 승격** — 비우면 주문 URL이 기간 제한 없이 열리는 운영 리스크(§근거) |
| ③진행상태·④준비노트·⑤열람이력 | **이 화면에 넣지 않는다.** 생성 완료 후 착지하는 **상세 페이지(L2) 섹션**으로 유지(이미 구현됨) |
| 기존 행사 편집 | **1차 범위 밖.** `EventFormDialog` 모달 그대로 유지. 편집 개선은 2차 트랙 |

### 행사 기간 필수 승격 근거 (코드 확인)

`OrderPage.jsx:127` — `eventData.end_date < today || eventData.start_date > today` → `expired` 처리.
날짜가 `NULL`이면 두 비교 모두 `false`(JS 추상 비교에서 `null`→0, 날짜 문자열→`NaN`)가 되어 **주문 페이지가 기간 제한 없이 항상 열린다.** 화면이 깨지진 않으나 학회 종료 후에도 주문이 유입될 수 있어 운영 사고 위험. → 생성 시점에 반드시 받는다.

## 사용자 시나리오

인싸이트/와박팀 직원(`events:edit`)이 학회 일정이 확정되면 사무실 PC에서 새 행사를 등록한다. **연 8일 운영이라 이 작업은 드물게 발생하고 손에 안 익는다** — 그래서 "고민 없이 몇 번 클릭하면 끝나는" 것이 핵심이다(타팀 이관 대비). 상단에서 연도·행사구분·주최학회를 고르면 행사명과 주문 URL이 자동으로 채워지고, 달력에서 기간을 2클릭하면 바로 "행사 만들기"를 누를 수 있다. 할인율·장소 같은 나머지는 접혀 있고, 지금 몰라도 만든 뒤 상세에서 채운다.

## 즉시 검증 (핵심 — 저장 시 몰아서 실패 금지)

기존에는 저장 버튼을 눌러야 검증 실패를 알았다. **입력 시점에 인라인으로 알린다.**

- [ ] **주문 URL 형식**: `/^[a-z0-9-]+$/` 위반 시 필드 하단 즉시 에러 — "고유 주소는 영문 소문자, 숫자, 하이픈만 사용할 수 있습니다."
- [ ] **주문 URL 중복**: 입력 **debounce 후 자동 조회**(`events.order_url_slug`). 결과를 필드 하단에 즉시 표시
  - 사용 가능 → "사용 가능한 주소입니다" (성공 색)
  - 중복 → "이미 사용중인 고유 주소입니다" (에러 색)
  - 조회 실패(네트워크) → "중복 검사 실패: {메시지}" — 저장은 막되 재시도 가능
- [ ] **행사명 비어있음** → 필드 하단 안내
- [ ] **행사 기간 비어있음** → 필드 하단 안내("주문 페이지가 열릴 기간입니다")
- [ ] **"행사 만들기" 버튼 상태**: 필수 3개(행사명·주문URL·행사기간)가 모두 유효할 때만 활성. 비활성 사유를 버튼 근처나 필드에서 알 수 있어야 함(비활성만 시키고 이유를 숨기지 말 것)

## 자동 채우기 규칙 (원본 로직 1:1 보존)

- [ ] **신규 생성 전용**(이 화면은 편집 모드 없음)
- [ ] `event_year` + `host_society` + `event_season`이 **모두 채워지면**:
  - 사용자가 행사명을 직접 건드리지 않은 경우(`!_nameTouched`)에 한해 → `name = "{연도} {주최학회} {행사구분}"`
  - `order_url_slug = "{society.slug_prefix}-{연도}-{season_eng}-{랜덤4자리}"` (랜덤 토큰 = 주소 추측 방지)
  - `season_eng`: 춘계학술대회→`spring` / 추계학술대회→`fall` / 연수강좌→`training` / 보수교육→`edu` / 세미나→`seminar` / 기타→`etc`. 목록 외 직접 입력 → `etc`
- [ ] 행사명을 **직접 수정하면 `_nameTouched` 플래그**가 서고, 이후 연도·구분·학회를 바꿔도 행사명을 덮어쓰지 않는다. `_nameTouched`는 **UI 전용 — DB upsert에서 제외**
- [ ] 행사명을 직접 입력했는데 주문 URL이 **아직 비어 있으면** → `slug = name.toLowerCase()` 공백→`-`, `[^a-z0-9-]` 제거

## 핵심 발견 (시안·구현 검수 시 반드시 확인)

1. **스텝·스테퍼를 만들지 말 것.** 건우님이 명시적으로 기각했다("페이지네이션한다고 좋은 게 아니야"). 단일 화면에서 끝나야 한다.
2. **필드 13개는 하나도 사라지지 않는다.** 3(자동조립) + 3(필수) + 7(선택)으로 **재배치**하는 것이지 축소가 아니다.
3. **`event_season` = Autocomplete freeSolo / `host_society` = select.** A5 시트가 뒤바꿔 기재했던 부분 — 실 코드 기준 본 시트가 정본.
4. **자동 조립 3필드는 별도 컨트롤.** 하나의 통합 입력으로 그리면 자동 채우기 의도가 사라진다.
5. **`_nameTouched` 잠금 보존.** 행사명 수동 수정 후에는 자동완성이 덮어쓰지 않아야 한다. DB에 보내지 않는다.
6. **행사 기간은 필수.** 비우면 주문 URL이 무기한 열린다(`OrderPage.jsx:127` 근거). 선택으로 되돌리지 말 것.
7. **주문 URL은 load-bearing.** QR·URL 복사·`site_settings.active_event_slug`(`/go` 리다이렉트)·고객 북마크의 앵커. 그래서 필수.
8. **중복 검사는 저장이 아니라 입력 중에.** "눌러봐야 아는" 실패를 없애는 것이 이번 개편의 핵심 중 하나.
9. **접힌 선택 영역에는 현재 값 요약을 보여준다.** 항목명만 나열하면 할인율 0% 같은 실수를 못 잡는다.
10. **선택 7개를 필수처럼 보이게 하지 말 것.** `*` 없음, 비워도 저장 버튼이 활성이어야 한다.
11. **할인율 단위 변환(UI % ↔ DB 소수) 표기 누락 금지.**
12. **판매 대분류: 빈 선택 = 전체 노출**("0개 노출" 아님, 2026-06-25 확정). 미지정 컬럼을 빈 배열로 덮어쓰는 회귀 주의(2026-06-25 전례).
13. **완료 후 상세 페이지 착지가 설계의 일부.** 여기서 ③④⑤로 이어진다.
14. **기존 편집 모달(`EventFormDialog`)은 1차에서 그대로 산다.** 이 페이지는 신규 경로만 추가 — 리스크 격리.
